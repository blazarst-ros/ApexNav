# ApexNav 飞行导航系统鲁棒性设计

## 目标与边界

本轮工作在已完成的 PX4 单一高度闭环基础上，对 Gazebo/PX4/MAVROS、RGB-D
适配、语义感知、二维栅格地图、全局/局部规划、轨迹执行和任务生命周期做一次
端到端审计。系统目标不是“某次能飞”，而是在输入正常时快速寻迹，在输入异常、
规划失败或控制偏差时能保持可解释、可恢复并最终安全停止。

本设计不把 Gazebo 真值接入飞行控制。PX4 本地位置控制器仍是唯一 Z 闭环；真值只
作为 SITL 验收与故障门控。二维规划器只负责 XY/yaw，不得改变巡航高度。

## 系统不变量

### 飞控与任务边界

- 任意会解锁的任务都必须在当前任务、当前 FCU 连接 epoch 内重新验证 PX4 高度参数。
- 起飞前必须同时具有新鲜 MAVROS 里程计、RGB、深度、规划器就绪状态，以及当前
  disarmed epoch 的新鲜 Gazebo 真值零点。
- 所有 PRESTREAM、起飞、保持、规划和故障保持 setpoint 都激活固定 PZ、忽略 VZ；
  不允许第二个外部 Z 反馈环。
- `/mavros/setpoint_raw/local` 只有 supervisor 一个业务发布者。轨迹服务器只发布
  有时间戳的规划参考，不可直接越过安全边界控制 PX4。
- 执行流断开、OFFBOARD/解锁丢失、定位或传感器 stale、持续高度偏差、规划器卡死
  都必须进入有界状态；停止时先清轨迹、锁存当前位置/巡航高度，再按故障策略保持或
  受控降落。

### 时间与坐标系

- 相机 RGB、深度、CameraInfo、相机位姿和语义结果以原始传感器时间为准；零时间戳、
  回退、未来数据或超过年龄上限的数据不得刷新健康看门狗。
- 所有地图、轨迹和可视化消息必须携带非零时间戳和明确的 `map` frame；消息接收时间
  只能用于本节点活性监测，不能伪装成源数据新鲜度。
- RGB-D 相机位姿只能由同一传感器时间附近的 MAVROS odometry 插值得到；不存在合格
  bracket 时丢帧，不外推陈旧位姿。

### 建图与避障

- 深度点只在相机/机体附近的飞行高度切片投影为二维障碍；地面、机体自反射、无穷远
  或最大量程回波不得成为占据端点。
- 最大量程样本只用于清自由空间；机体安全泡内的历史占据在每帧膨胀前清除。
- 原始占据、膨胀占据、ESDF 与 footprint 碰撞检查必须采用一致地图版本和相同 frame。
- 安全检查可立即打断轨迹；普通 frontier/语义目标变化只能在最小提交时间或最小进度
  之后触发周期重规划，避免目标抖动。

### 规划与轨迹执行

- 规划轨迹消息必须通过结构、长度、有限值、正时长和时间 epoch 校验；畸形消息不可
  越界访问或替换当前有效轨迹。
- 轨迹参考必须按 odometry 跟踪误差渐进降速；误差达到冻结阈值时保持参考点，持续或
  硬碰撞错误由 FSM 有界停止并重新规划。
- `PLAN_TRAJ` 阶段使用独立的 phase/total watchdog；`EXEC_TRAJ`/`REPLAN` 使用命令
  新鲜度 watchdog，二者计时 epoch 不得混用。
- 目标接近失败可回退普通探索一次并获得新的 phase budget，但总规划 deadline 不重置。

## 采用方案

采用“单一安全边界 + 强消息契约 + 有界恢复”的方案：supervisor 统一持有 PX4 输出和
任务状态；上游节点发布带来源时间的不可变数据；地图与轨迹节点在入口拒绝无效数据；
所有恢复路径由独立 deadline 约束。

未采用让规划器直接发布 MAVROS setpoint 的方案，因为这会产生多发布者与停止竞态；
也未采用 Gazebo 真值纠正 setpoint 的方案，因为该做法会掩盖 PX4 estimator 故障并使
仿真控制架构无法迁移到真实飞行器。

## 验收层级

1. 纯函数/单元测试覆盖时间戳、setpoint mask、PX4 profile、真值 debounce、轨迹消息
   校验、目标锁定、重规划 deadline 和跟踪渐进率。
2. launch/config 契约测试覆盖 topic、frame、唯一控制发布者、Gazebo 专用真值门控及
   实机默认禁用真值门控。
3. 完整 catkin 构建和全量测试零失败。
4. 新一次 SITL 动态验收要求：真值与 MAVROS AGL 稳态差不持续超过 0.15 m；地图无
   距离环墙/地面墙；轨迹持续输出且实际 XY 前进；安全停止后无旧轨迹命令复活。

第 4 层必须用修改后的 PX4 进程和新日志证明。旧日志只能证明根因，不能作为修复后的
飞行成功声明。
