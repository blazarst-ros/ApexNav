双机禁用 agent vs 单智能体基座 对比实验说明
================================================

目的
----
检验 lite-multiagent（双机版）在只启用 1 个 agent 时，导航/判断逻辑是否与
lite-apexnav（单智能体基座）一致。两组使用相同的 hm3dv2 val episode（从
episode 0 起连续 20 条）与相同的 success_distance=1.2。

已完成的准备
------------
1. 新建 /home/uuufo/ApexNav-lite-single，克隆 lite-apexnav 单智能体基座（原样代码）。
2. /home/uuufo/data -> /home/uuufo/ApexNav/data 软链接（基座把数据解析到该路径）。
3. 基座已 catkin_make 构建完成（devel/lib/exploration_manager/exploration_node 等）。
4. 修复了双机版两处话题不匹配（仅影响单 agent 模式，多 agent 模式不受影响）：
   - habitat_evaluation_multiagent.py：单 agent 分支的 ITM/检测云话题改为
     /clip/agent_0/cosine_score、/detector/agent_0/clouds_with_scores
     （原为无后缀 /clip/cosine_score、/detector/clouds_with_scores，与
     双机版 C++ MapROS 订阅不匹配，导致 C++ 收不到语义数据）。
   - habitat_evaluation.py（双机版自带的单机脚本）：同样修复 + 订阅话题改为
     /habitat/plan_action_agent_0（原为 /habitat/plan_action，双机版 C++
     只发布带后缀话题）。
5. 修复了 C++ 的 num_agents 读取（exploration_fsm.cpp）：原来用 private 命名
   空间读（~num_agents），而 launch 的 rosparam 加载到全局命名空间
   （/num_agents），导致单 agent 配置（num_agents=1）读不到、C++ 仍按 2 个
   agent 初始化（MapROS 读全局所以两边不一致）。已改为读全局参数，并重新
   catkin_make（双机版 devel 已更新，无需用户再构建）。
   注意：双机模式（multiagent_lite yaml 提供 num_agents: 2）行为不变。
6. 基座脚本（组A）移植了 test_episode_count 批量评测功能：原版基座脚本只有
   "单条（test_epi_num）"与"跑完所有剩余"两种模式，无法只跑 20 条；直接传
   test_episode_count=20 会因 yaml 无该字段而报 hydra override 错误。已按
   lite-multiagent 版的写法最小移植（habitat_evaluation.py +33/-8、
   config yaml 加 test_episode_count: -1），仅影响评测控制，不改导航/感知
   逻辑。三组命令均已预演验证（hydra compose 通过）。
修复前双机版 C++ 只认 /clip/agent_0/* 与 /detector/agent_0/* 话题。

⚠ 两组实验必须串行执行（共享 roscore 端口 11311、VLM 端口 12182/12184、GPU）。
先完整跑完组 A，按反序 Ctrl-C 停掉所有终端，再跑组 B。

  CLIP_DOWNLOAD_ROOT=/home/uuufo/ApexNav-lite/RuntimeData/model-cache/clip
- 评测命令统一加 success_distance=1.2，与双机测试说明一致。

────────────────────────────────────────────────────────────────
补充实验（可选，验证标签归一化差异）
────────────────────────────────────────────────────────────────
静态分析发现：组A 对目标标签做了归一化（HM3D: sofa→couch、
tv_monitor→tv、plant→potted plant），组B 没有。但 episode 0-19
全部是 cabinet，此差异不会体现。

若要验证，可加跑下面任一段（方法相同，两组都跑相同段再对比）：
  - episode 0-44（45 条）：含 cabinet(0-34) + sofa(35-40) → 一次覆盖两类
  - episode 0-134（135 条）：额外含 plant(125-132) → 覆盖 sofa + plant
注意：脚本的批量模式从 episode 0 起连续跑（test_episode_count=N），
不支持从中间段开始；test_epi_num 只跑单条。所以用"更大的
test_episode_count"一次覆盖，分析时只看目标类别区间。

例（两组都跑 0-44，覆盖 sofa 段）：
  python habitat_evaluation_multiagent.py --dataset hm3dv2 \
    test_episode_count=45 \
    video_output_path=videos/test_single_hm3dv2_sofa \
    habitat.task.measurements.success.success_distance=1.2
